# Fresh Chat Handoff

## 目标与边界

把关键上下文移交给全新对话，而不是复制完整历史的分支。这里的“压缩”指提炼交接摘要，不等于对原对话执行系统级上下文压缩；不要声称已执行 `/compact`、已清空原上下文或已释放原对话容量。

本技能不是后台容量监控器。只在可见上下文用量、系统提示、用户提醒或明显较长的对话让你能够察觉上下文偏满时，尽量提前询问；不编造剩余百分比，不保证每次赶在系统自动压缩前。技能被安装不等于始终被加载或持续运行。

## 判断是否已获授权

- **只是察觉偏满，或用户只问“快满了怎么办”**：先问：“当前对话已经比较长，要不要整理交接摘要，再开启全新的独立对话继续？不创建分支，也不复制完整历史。” 等用户同意，不创建新对话。
- **用户明确说“用交接摘要开一个全新对话”“上下文快满了，按这个方式操作”或确认了上一条询问**：已授权本次创建，可以执行，不需要重复询问。
- **用户只要求摘要、询问能力、说“以后先问我”，或明确“先别执行”**：只完成指定部分，不创建对话。不把未来偏好当成本次创建授权。
- **裸调用 `$fresh-chat-handoff`，没有明确执行意图**：简要说明后询问是否现在创建。

## 提炼交接摘要

只使用当前可见并有依据的信息；不声称读过不可见的历史。按实际需要保留下列内容，省略空项：

1. 用户当前目标、最新明确要求与已确认的协作偏好。
2. 已确认结论、规则、限制及明确不做的事；临时推测标明未确认。
3. 已完成内容、关键文件/入口、已执行的验证与仍未验证的部分。
4. 当前进度、阻塞、未完成事项和下一步。
5. 如涉及本地工作：当前实际项目/执行主机、工作目录、必要的未提交改动或并发风险。只记录已知状态，不为凑摘要全仓扫描。

不复制整段聊天、无关日志、重复工具输出、token、密码、私钥或其他不必要的敏感信息。用户纠正后的要求优先于旧结论。

把可直接放入新对话的开场信息写成：

```text
这是由旧对话通过交接摘要创建的全新独立对话，不是分支。
你只收到下面这份摘要，不应声称继承了完整聊天历史。

[按实际需要填写交接摘要]

开始后先读取并遵循当前工作目录适用的 AGENTS.md / 项目指令。
[写明本次已授权继续的具体事项；若用户仅要求迁移，则只确认收到摘要，等待下一条提问。]
```

正在进行的任务如果需要交接状态文件，按适用项目规则在安全里程碑更新；本技能本身不要求创建 SPEC、PLAN、SESSION 或 TASKS，也不写入正式记忆。

## 创建全新对话

先检查当前环境确实提供了哪些工具；安装技能不会新增工具能力。若有本地项目操作，先遵循当前工作目录适用的 `AGENTS.md` / 项目指令。

### 有 Codex 桌面端对话工具

- 使用 **`create_thread`**，把交接摘要作为新对话的初始 `prompt`。**不要使用 `fork_thread`**，也不要用子代理代替用户可见的新对话。
- 本次明确的目标项目/主机优先。否则保持当前实际项目和执行环境；调用 `list_projects` 从返回值匹配项目，并使用真实 `projectId`。不猜 ID，也不把同名项目当成同一目录。
- 本地项目通常使用 `target.type = "project"` 与 `environment.type = "local"`，沿用实际已在使用的目录（包括已有工作树目录）。没有项目时使用 `projectless`。不要为这次交接额外创建 Git 工作树；云端或不同主机迁移按工具能力与用户明确要求选择，无法保留当前环境时先询问，不静默切换。
- 不擅自指定模型、改分支或扩大新对话的执行范围。摘要只交接已确认上下文，不替新对话授权额外任务。
- 调用成功后按返回结果使用真实 `threadId` / `hostId`；若仅返回 `clientThreadId`，说明仍在准备，不能当成正式 `threadId` 调用其他工具。
- 就绪后使用一次有界的 `wait_threads` 确认启动情况。用户要求在新对话继续或打开它时，使用 `navigate_to_codex_page`；不需要再向其他已有对话发送消息。
- 只在创建成功后使用应用支持的 `::created-thread{threadId="..."}` 展示入口；准备中只能使用真实返回的 `clientThreadId`。汇报创建成功、准备中或失败，不把提交请求等同于新对话已完成任务。

### 缺少创建对话工具

输出完整可复制的开场摘要，明确说明“摘要已准备好；当前环境不能自动创建新对话，请手动新建空白对话并粘贴”。不要声称已经创建，不用 CLI 的 resume/fork 冒充全新对话，也不通过未经授权的 GUI 操作绕过边界。

### 创建失败或返回结果不明确

- 保留摘要，报告具体状态，不盲目重试创建以免产生重复对话。
- 有已返回的 ID 时优先查询该对话状态；结果仍不明确时说明不确定，并等用户决定是否重试或手动创建。

## 收尾

说明这次传递的是摘要，不是完整历史，且不是分支。原对话及已有分支默认保留；没有额外授权不删除、不归档、不关闭旧对话，不声称这里的历史已被压缩或删除。

不会在本次技能制作、安装、测试或纯能力说明中顺便创建示例对话。跨电脑分享的是技能流程；本机的原聊天、项目状态与 Memories 不会随技能包自动迁移。
